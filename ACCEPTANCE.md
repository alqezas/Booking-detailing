## Автоматические проверки (все зелёные на момент сдачи)

| Набор | Где | Результат |
|---|---|---|
| `pnpm typecheck` | TS strict, приложение + скрипты + общий код функций + service worker | без ошибок |
| `pnpm test` — модульные | роутер намерений (3+3 примера вопросов, даты в часовом поясе студии), цикл агента с подставным клиентом модели, разделение инструментов клиента/владельца, контраст акцента, ICS, телефоны, `business.json` | 35/35 |
| `pnpm test:db` — SQL/интеграционные на локальном Supabase через PostgREST | см. ниже | 34/34 |
| `pnpm test:e2e` — Playwright, Pixel 7 + Desktop Chrome, локальная сборка | запись клиентом → запись видна владельцу; двойной тап; гонка двух устройств за один слот; офлайн; изоляция PWA; глубокие ссылки; reduced motion; стекло | 11/11 (+1 пропуск: гонка только на телефоне) |
| `E2E_BASE_URL=<боевой сайт> pnpm test:e2e` | то же против Vercel + облачной БД (вход владельца пропущен — см. ниже) | 11/11 |
| `pnpm tenant:verify graphite`, `severny` против боевого сайта | HTML студии, адрес внутри scope, глубокая ссылка, манифест (id/start_url/scope/maskable), иконки, worker, данные и слоты из облачной БД | все пункты ✓ |

SQL/интеграционные (`tests/db`): одновременные 12 запросов на однобоксовый слот → ровно 1 успех;
два подходящих бокса → 2 успеха в разных боксах, затем «занято»; двухдневная услуга занимает бокс через ночь;
блокировка бокса через общую таблицу занятости (и не ложится на существующую запись); перенос атомарный —
при занятом времени запись остаётся на месте; повтор запроса возвращает ту же запись и тот же токен,
5 параллельных двойных нажатий → одна запись, чужое использование ключа → 409; в БД только хэш токена;
отмена по правилам и после дедлайна; цена записи не меняется при смене цены услуги; оплаты, возвраты,
переплата возврата запрещена, статистика разделяет заезды / готовые работы / полученные деньги / прогноз;
DST (Europe/Berlin) и UTC+5; RLS: владелец не видит и не меняет чужое, составные FK не дают связать чужой бокс,
anon не читает ни одной таблицы и не вызывает служебные функции, токены и push-подписки недоступны даже владельцу,
хранилище — только своя папка; публичной регистрации нет; пользователь без членства не видит ничего;
outbox: одна задача на подписку, перенос отменяет старую и создаёт новую, отмена гасит, lease и SKIP LOCKED,
перехват после истечения lease, чужой воркер не может завершить, ретраи с backoff, удаление мёртвых
подписок, в образце уведомления не ставятся; активация удаляет демо; переиздание конфига сохраняет записи,
оплаты и фото владельца, убранная услуга скрывается, а не удаляется.

Вёрстка (`tests/e2e/layout.spec.ts`): на 360/390/768/1024/1440 px нет горизонтальной прокрутки, заголовок
шапки, кнопка «Записаться» и все разделы стоят на одной линии контента (вторая — только у парных блоков);
вход в кабинет помещается на 360/390/1280 px. Проходит локально и на боевом сайте.

## Ручные проверки

- Браузер (телефон 375 px и ПК 1366 px), локально и на боевом сайте: главная (фото, стеклянная кнопка
  движется с фото, надпись чёткая, «Запись в студию», карточки, услуги, работы, контакты, плавное появление),
  шторка записи по шагам с зачёркнутыми занятыми слотами, «Моя запись», помощник, кабинет (локально):
  «Машина принята», оплата, мгновенное обновление показателей, настройки и галерея.
- Конвейер на третьей студии (локально): `tenant:new` → `validate` (заглушки помечены) → `publish` →
  сборка → `verify --activate` отклонён из-за заглушек → заполнение → активация прошла, демо-записи удалены;
  две другие студии продолжили работать.
- Облако (`tests/integration/cloud-check.ts`): помощник клиента отвечает по реальным услугам/слотам/адресу;
  помощник владельца — по записям и деньгам; владелец GRAPHITE → Северный Бокс: 403; аноним → 401;
  диспетчер без секрета → 401; публичная регистрация → 422 `signup_disabled`; в бандле нет серверных ключей.
- Цикл инструментов через настоящую edge-функцию прогнан с **локальным симулятором** OpenAI-API
  (`tests/integration/fake-llm.ts`): первый вызов `tool_choice: required`, несколько раундов, только инструменты
  своей области, учёт токенов в бюджете. Это **не** проверка настоящей модели.

## Не проверено / внешние зависимости

| Что | Почему | Как закрыть |
|---|---|---|
| Ответы настоящей LLM | ключ модели не передан; помощники сейчас в режиме «без ИИ» (честно помечено) | `npx supabase secrets set LLM_API_KEY=… LLM_MODEL=…` |
| Доставка Web Push до устройства | обе студии — образцы, им уведомления не положены; доставка через push-сервисы не проверялась | активировать студию, на телефоне включить напоминание, проверить уведомление (iPhone — только из установленного на «Домой» приложения, iOS 16.4+) |
| Установка на реальных iPhone/Android, standalone-режим | реальных устройств не было; проверены манифест, иконки, scope и офлайн в Chromium | открыть ссылку на телефоне → «На экран „Домой“» |
| Вход в кабинет на боевом сайте через браузер | автоматизация не вводит пароль на не-локальном сайте | войти с паролем из `.secrets/owners.local.txt` |
| Письма восстановления пароля | в Supabase не настроен свой SMTP (встроенный — с жёсткими лимитами) | Supabase → Auth → SMTP |
| Фотографии студий | временные изображения, сгенерированные скриптом | заменить фото владельца в `tenants/<slug>/images` или в кабинете |
| Ограничение по IP за прокси Supabase | лимит по IP опирается на заголовки прокси; страхуют лимиты на телефон и студию | — |
