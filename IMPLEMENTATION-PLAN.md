## Решения (кратко)

- **Bottom sheet:** вместо shadcn Drawer используется `BottomSheetSwitcher` из Astryx — одна шторка
  на весь сценарий без второй дизайн-системы и без Tailwind (в проекте нет Tailwind-компилятора,
  AGENTS.md запрещает утилитарные классы). Смысл требования — «последовательная шторка, одна ветка
  компонента» — сохранён.
- **Тема:** собирается во время работы из `defineTheme(extends: neutral)`, потому что акцент хранится в БД
  и меняется владельцем. Из одного цвета выводятся заливка кнопок (≥ 4.5:1 с белым) и цвет акцентного
  текста (≥ 4.5:1 на чёрном) — `shared/color.ts`.
- **Хостинг:** Vercel (по третьему промпту); сборка полностью статическая и подойдёт и для Cloudflare Pages.
  Деплой — `vercel build` + `vercel deploy --prebuilt`.
- **Стекло:** у liquid-gl цель стекла становится неинтерактивной, поэтому стекло — отдельный декоративный слой
  под настоящей кнопкой. Снимок для кнопки на фото берётся только с элемента фотографии — буквы соседних
  разделов в линзу попасть не могут; надпись — обычный DOM поверх линзы.
- **Фото:** фото из `business.json` раздаются сайтом (`/s/<slug>/media/…`); загрузки владельца — в бакет
  `tenant-media/<tenant_id>/…`, писать туда может только участник студии.
- **Токен клиента:** детерминированный HMAC(booking, idempotency key) — повтор того же запроса возвращает тот же
  токен, а в БД лежит только SHA-256.
- **Многодневные услуги:** бокс занят непрерывно на `длительность + подготовка`, включая ночи; часы работы
  ограничивают только момент приёма (короткие услуги ещё и должны закончиться до закрытия).
- **IP для лимитов** берётся из заголовков прокси; дополнительно стоят лимиты на телефон и на студию,
  которые подделкой заголовков не обойти.
- **Пароли владельцев** создаются конвейером и пишутся в `.secrets/owners.local.txt` (git-ignored), не в консоль.

### Решения бьюти-вертикали

- **Ресурс = мастер или место.** Услуга занимает один подходящий ресурс на `длительность услуги + опции + буфер`.
  «Любой свободный мастер» = `p_resource null`: сервер перебирает подходящих мастеров в подтранзакциях до первого,
  которого пропускает `EXCLUDE`. Выбранный конкретный мастер пробуется только он.
- **Смены мастеров сужают часы студии.** Начала записи генерирует расписание студии (исключения, выходные, часовой
  пояс как раньше), а мастер подходит, только если вся услуга (без буфера) помещается в его смену и у него нет
  выходного. Смену шире часов студии запрещает `tenant:validate`.
- **Опции — снимок.** В `bookings.tire_params` (`kind: addons`) лежат выбранные опции с ценами и минутами в момент
  записи; правка цен в кабинете старые записи не меняет. Клиент передаёт только ключи опций.
- **Перенос клиентом** — по тому же токену и до того же дедлайна, что и отмена; при конкретном мастере ищется время
  только этого мастера. Неудача (`SLOT_TAKEN`) оставляет запись и её занятость нетронутыми (update в подтранзакции).
- **Telegram** — только действия клиента (новая запись, перенос, отмена): владелец сам знает, что сделал в кабинете.
  Образцу и демо-записям задачи ставятся со статусом `skipped`, причина видна в кабинете. Токен бота — секрет
  функций `TELEGRAM_BOT_TOKEN`; chat id хранится в `tenants`, читается только участниками студии и сервис-ролью.
- **Статистика.** `owner_stats_for` добавляет `upcoming`/`upcoming_value` (подтверждённые записи с текущего момента)
  отдельно от завершённых визитов, неявок и полученных денег; тот же период и часовой пояс у UI и помощника.
- **shadcn/ui Drawer не используется** (решение прежнего этапа сохранено): в проекте нет Tailwind-компилятора,
  AGENTS.md запрещает утилитарные классы; последовательная шторка — `BottomSheetSwitcher` Astryx, одна ветка.
- **Стекло.** Нижняя навигация и панель выбора у бьюти — молочное стекло liquid-gl с сильным frost и белым tint:
  буквы прокручиваемого контента под ним не читаются; подписи кнопок — обычный DOM над линзой и остаются чёткими.
- **Телефон клиента** в бьюти-студии нормализуется по стране студии (русскоязычная студия в Праге → +420).
